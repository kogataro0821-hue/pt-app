# 説明書（契約者用 / 管理者用）

配布する PDF と、その作り方一式です。

| 誰に渡すか | ファイル |
|---|---|
| 契約者 | `pdf/PT-Manager-使い方ガイド-契約者用.pdf`（33ページ） |
| 管理者（トレーナー） | `pdf/PT-Manager-運用ガイド-管理者用.pdf`（32ページ） |

---

## いちばん大事なこと

**画面を変えたら、この説明書も直してください。**

説明書は、ボタンの文言や注意書きを**実物どおりに**書いてあります。
アプリだけ直して説明書を置き去りにすると、
「書いてあるボタンが無い」という、いちばん困る状態になります。

そうならないように、**画面写真を撮り直す仕組みごと**ここに置いてあります。
文章を直して、写真を撮り直して、PDFを作る。この3つで終わります。

---

## 直すときの手順

### ケース1: 文章だけ直す（ボタンの位置も名前も変わっていない）

1. `client.html` か `admin.html` を直す
2. `node docs/manual/tools/topdf.mjs`

これだけです。写真は撮り直しません。

### ケース2: 画面が変わった（文言・並び・新しい機能）

```bash
# 1. ダミーの写真を作る（1回作れば、消さないかぎり不要）
python3 docs/manual/tools/make_photos.py

# 2. 画面に写る架空の記録を作る（seed.js ができる）
python3 docs/manual/tools/make_seed.py

# 3. 確認用のビルドを作る（Firebase と AI を偽物に差し替えたもの）
npx vite build --config docs/manual/tools/vite.harness.config.mjs

# 4. 画面写真を撮る
node docs/manual/tools/shoot.mjs

# 5. 縦長の画面を組み直して、画像を軽くする
python3 docs/manual/tools/finish_images.py

# 6. HTML を直してから、PDF にする
node docs/manual/tools/topdf.mjs
```

Playwright が要ります（`npm i -g playwright`）。

## 仕組み

### アプリ本体は1行も書き換えません

`tools/vite.harness.config.mjs` の中だけで、次の3つを偽物に差し替えています。

| 差し替えるもの | 何をする偽物か |
|---|---|
| `firebase/app` `firebase/auth` `firebase/firestore` | メモリの中だけで動く。通信しない |
| `apps/web/src/features/ai/gemini.ts` | AIを呼ばず、決まった答えを返す |

**本体を書き換えて撮る方式にはしていません。**
戻し忘れたまま公開してしまう危険があるためです。
この設定ファイルを使わなければ、偽物は1つも読み込まれません。

### 写っているのは全部、架空のものです

- 契約者「田中 花子」「鈴木 太郎」「佐藤 みどり」は、`tools/make_seed.py` の中で作った架空の人です
- 食事の写真と栄養成分表示は、`tools/make_photos.py` が描いています。実在の商品ではありません
- 日付は 2026-08-29 に固定してあります。撮り直しても同じ絵になります

このリポジトリは公開なので、**実際の契約者のデータは1件も入れません。**

### 誰を映すかは URL で切り替えます

| URL の末尾 | 誰として見るか |
|---|---|
| `?as=client`（既定） | 田中 花子（契約者・パスワード変更済み） |
| `?as=new` | 鈴木 太郎（初回ログイン。パスワード変更画面が出る） |
| `?as=admin` | 管理者 |
| `?as=out` | ログアウト状態（ログイン画面） |

## ファイルの置き場所

```
docs/manual/
├ README.md                   ← これ
├ client.html                 ← 契約者用の本文
├ admin.html                  ← 管理者用の本文
├ style.css                   ← 2冊で共通の体裁（A4・余白・囲み・表）
├ img/                        ← 画面写真（撮り直すと全部入れ替わる）
├ pdf/                        ← 配布するPDF
└ tools/
   ├ vite.harness.config.mjs  ← 偽物に差し替えるビルド設定
   ├ stubs/                   ← 偽 Firebase・偽AI・架空データ
   ├ make_photos.py           ← ダミー写真を描く
   ├ make_seed.py             ← 架空の記録を作る
   ├ shoot.mjs                ← 画面写真を撮る
   ├ finish_images.py         ← 縦長を組み直す・軽くする
   └ topdf.mjs                ← PDFにする
```

`tools/out/` と `tools/stubs/seed.js` と `tools/photos/` は作られるものなので、
消しても手順どおりに作り直せます。

## 気をつけること

### 撮れなかったら止まります

`shoot.mjs` は、1枚でも撮れないと**エラーで終わります**。
「カードが見つかりません: からだ」のように、どの画面かが出ます。

これはたいてい、**アプリ側の見出しやボタンの文言を変えた**ということです。
`shoot.mjs` の中の文字列を、新しい文言に直してください。
そのうえで、説明書の本文にも同じ文言が書かれているはずなので、そちらも直します。

### 画像が空のまま組まれないようにしてあります

`topdf.mjs` は、読めなかった画像があるとエラーで終わります。
PDFになってから空欄に気づくと、どの章か探すのに時間がかかるためです。

### 日本語フォント

`Noto Sans CJK JP` が入っている環境で作ってください。
入っていないと、豆腐（□）だらけのPDFができます。

### 章立ては両方そろえてあります

説明書に章を足したら、**先頭の目次（`.toc`）にも足してください。**
目次は手書きです。自動では増えません。
