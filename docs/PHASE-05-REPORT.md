# Phase 5 報告 — カレンダー

## 1. できたこと

### URLと画面が連動するようになりました

これまで画面の切り替えを内部の状態だけで持っていたため、
ブラウザの戻るボタンが効かず、特定の画面を開き直すこともできませんでした。
`react-router-dom` を入れて、URLと画面を対応させました。

| URL | 画面 |
|---|---|
| `/` | 契約者→自分のカレンダー ／ 管理者→契約者一覧 |
| `/clients` | 契約者一覧 |
| `/clients/new` | 契約者の追加 |
| `/clients/〈ID〉/settings` | 目標・権限の設定 |
| `/c/〈ID〉` | その人の今月のカレンダー |
| `/c/〈ID〉/m/2026-08` | 指定した月のカレンダー |
| `/c/〈ID〉/d/2026-08-27` | その日の画面 |

これで手に入るもの:

1. ブラウザの戻るボタンが効く
2. 「この日を見て」とURLを渡せる
3. ホーム画面に追加したとき、開きたい画面を指定できる

URLを直接開いても動きます。GitHub Pages は存在しないパスに `404.html` を返しますが、
その中身を `index.html` と同じにしてあるため（`deploy.yml`）、
読み込まれたあとにアプリ側が正しい画面を描きます。

### 月カレンダー

- 日曜始まりの7列。前後の月がはみ出すぶんも埋めるので、月によって高さが変わりません
- 今日のマスは枠と背景で強調
- 印は4種類（下記）
- 月の切り替えは ‹ ›。今月以外を見ているときは「今月に戻る」が出ます

**印の設計**

| 印 | 意味 |
|---|---|
| 緑の点 | 食事の記録あり |
| 青の点 | 運動の記録あり |
| 橙の点 | 体重の記録あり |
| 下線 | 確定済み／AI評価済み |

★ 確定済みだけ点ではなく**下線**にしました。
点が4つ並ぶと、スマホの画面では色の違いを見分けられなくなるためです。
下線なら、色が見分けにくい方でも形で区別できます。

★ マスに数字（カロリー等）は出しません。月表示に数字を詰めると読めなくなります。
数字はその日の画面で見ます。

### その日の画面

- 前後の日へ移動できます
- **体重・体脂肪率**を入力して保存できます（Q6の決定を反映）
- 目標体重が設定されていれば併記します
- 食事・運動・合計の枠は、破線の「これから作る枠」として置いてあります

編集できない日（確定済み／ウィンドウ外／未来の日）は、入力欄が使えなくなり、
理由が文章で出ます。

### 管理者の導線

- 契約者一覧 → 名前をタップ → **その人のカレンダー**
- 契約者一覧 → 「設定」 → 目標・権限の画面
- 契約者のデータを見ている間は、画面上部に **「閲覧中 〇〇」** の帯が出ます

★ この帯は事故防止のためです。管理者は複数の契約者を行き来するので、
いま誰の記録を触っているのかが常に見えていないと、別人のデータを書き換えてしまいます。

## 2. 通信量の設計

カレンダーは **月に1回のクエリ**で必要な情報をすべて取ります。

日ごとに読むと1か月で31回の通信になり、無料枠を無駄に消費します。
そのため、印に使う情報（食事の有無・運動の有無）は
日ドキュメントに要約して持たせる方式にしました。
食事を書き込むときに同時に更新します（Phase 6）。

## 3. ★ 見つけて直した権限の穴

`clients/{cid}/measurements/{date}` が **read/write 一括許可**になっていました。

```
match /measurements/{date}    { allow read, write: if canRead(cid); }
```

ドキュメントIDが日付なのに、過去編集ウィンドウが適用されていません。
つまり契約者が **何年前の体重でも書き換えられる**状態でした。

`days` と同じ制限に直しました。

```
match /measurements/{date} {
  allow get, list: if canRead(cid);
  allow write: if mayEdit(cid, date);
}
```

権限テストに再発防止のテストを追加しています。

## 4. テスト

| 種類 | 件数 | 実行場所 |
|---|---|---|
| 単体テスト | 79件（+23） | CI・毎回 |
| 権限テスト | 65件（+8） | CI・毎回（失敗したら公開しない） |

**追加した単体テスト（日付ロジック）**

日付の扱いは、時間帯の取り違えで静かに1日ずれる事故が起きやすい場所です。
そのため純粋な関数として `@pt/core` に切り出し、次を機械的に検証しています。

- 日本の23時が「当日」になること（UTCで計算すると前日になってしまう）
- うるう年（2024-02-29 は有効、2025-02-29 は無効）
- カレンダーのマス目が必ず7の倍数で、日付に隙間も重複もないこと
- 過去編集ウィンドウの境界（7日前は可、8日前は不可）

**追加した権限テスト**

- 契約者は自分の月ぶんの日データを一覧できる／他人のは一覧できない
- 契約者は他人の体重を書き込めない
- 10日前の体重は自分では書けない（管理者は書ける）
- measurements にも同じウィンドウが適用される

## 6. 動作確認の手順

**契約者として**

1. `test01` でログイン → カレンダーが出る
2. 今日をタップ → 体重を入れて保存
3. カレンダーに戻る → 今日に橙の点が付いている
4. **ブラウザの戻るボタン**で日別画面に戻れる
5. 8日以上前の日を開く → 入力欄が使えず、理由が出る

**管理者として**

1. ログイン → 契約者一覧
2. `test01` の名前をタップ → その人のカレンダー、上に「閲覧中 test01」
3. 同じ日を開く → 契約者が入れた体重が見える
4. 8日以上前の日でも入力できる
