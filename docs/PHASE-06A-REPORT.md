# Phase 6A 報告 — 食事の記録と合計

Phase 6 は量が多いため、前半（食事）と後半（運動・1日確定）に分けています。
これは前半の報告です。

## 1. できたこと

### 食事の記録

「+ 食事を追加」で `1食目` `2食目` … と増やしていきます（Q12の決定）。
食事の名前はその場で書き換えられるので、「朝食」「プロテイン」でも構いません。

各食事の中に食材を並べます。食材1件はこう入れます。

```
食材の名前   鶏むね肉
食べた量     150 g
100gあたり   191 kcal / P 19.5 / F 11.6 / C 0
```

入力している最中から「この食材ぶん 287kcal P29.3 F17.4 C0」と出ます。
保存してから気づくのではなく、入れながら確認できる形にしました。

### 食品マスタが使いながら育つ（Q13の決定）

保存すると、その食材は自動的にあなたの食品マスタに残ります。
次からは名前を打つだけで候補に出て、栄養値が自動で入ります。

- 前方一致を先に、部分一致をあとに並べます（「とり」で「焼きとり」が先に出ないように）
- よく使う食材ほど上に来ます
- 共通マスタの食品には「共通」の印が付きます

マスタは一度読んだらキャッシュし、食材を入力するたびの通信は発生しません。

### 合計と目標との差

その日の合計と、目標（例: 1600kcal / P130 F50 C200）との差を出します。
超過はオレンジ、不足は青。**良し悪しの判断はしません**。それは評価（Phase 10）の役目です。

## 2. ★ 設計書 §15 の絶対条件

> 食材の合計 == 食事の合計 == その日の合計

これが1kcalもズレないことを、テストで機械的に検証しています。

支えているのは2点だけです。

1. 栄養値を **1/1000単位の整数**で持つ（浮動小数点数を使わない）
2. 丸めを「食材1件につき1回」に限定し、合計では一切丸めない

整数の足し算には結合法則が成り立つため、**どんな順序で足しても、何段階に分けて足しても、
結果は完全に一致します**。浮動小数点数ではこれが成り立ちません。

検証している内容:

- 日合計 == 食材を平らに並べた合計
- 日合計 == 食事合計を足したもの
- 食事の並び順を変えても日合計は変わらない
- 食材の並び順を変えても食事合計は変わらない
- **端数の出る量（3.3g, 6.6g, 9.9g…）を63件足しても一致する**
- 空の食事があっても、食事が0件でも壊れない

### 画面の数字が合わないように見える件

内訳の表示は小数第1位に丸めています。そのため、目で足すと1桁ずれて見えることがあります
（例: 67.6 + 5.9 = 73.5 だが、合計は 73.4 と表示される）。

**正しいのは合計のほうです。** 内訳が丸められているだけで、内部の計算は狂っていません。
画面にもその旨を書いてあります。

## 4. ★ 権限の穴をもう1つ塞ぎました

管理者は契約者ごとに「自分で食品を登録できる」権限を切れます（設計書 §21）。
ところが Rules 側は `allow read, write: if canRead(cid)` のままで、
**画面で隠しているだけ**でした。設定をオフにしても、実際には登録できてしまいます。

Rules で判定するよう直しました。レシピも同じです。

```
match /foods/{foodId} {
  allow read: if canRead(cid);
  allow write: if isAdmin() || (isClient(cid) && mayCreateFood(cid));
}
```

権限が設定されていない古いデータでも動くよう、既定は `true` にしてあります。

## 5. データの置き方

```
clients/{cid}/days/{date}/meals/{mealId}
  { order, label, memo, items: [...], totals, createdAt, updatedAt }
```

食材は**食事ドキュメントの中の配列**です。さらに下位コレクションにすると、
1食を表示するだけで食材の数だけ通信が発生します。1食あたりの食材は数個なので、
まとめたほうが速くて安くて壊れにくくなります。

栄養値はここだけ**内部表現（整数）のまま**保存します。
目標値や食品マスタは読みやすさを優先して人間の単位で保存していますが、
確定した記録の合計が1kcalもズレないことのほうが重要だからです。

## 8. 動作確認の手順

1. `test01` でログイン → 今日を開く
2. 「+ 食事を追加」→「1食目」ができる
3. 「+ 食材を追加」→ 名前 `白米` / 量 `180` / 100gあたり `156` `2.5` `0.3` `34.6`
4. 入力中に「この食材ぶん 281kcal …」と出るのを確認 →「追加する」
5. もう1つ食材を足す（`鶏むね肉` / `150` / `191` `19.5` `11.6` `0`）
6. 「この食事の合計」が 568kcal になる（281 + 287）
7. 一番下の「この日の合計」と一致していることを確認
8. **もう一度「+ 食材を追加」で `白米` と打つ** → 候補に出る → 選ぶと栄養値が自動で入る
9. カレンダーに戻ると、その日に**緑の点**が付いている
