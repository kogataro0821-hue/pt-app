# 追加仕様の報告 — ログインポイント

毎日ひらくとポイントがたまり、管理者が自由に付けたり減らしたりできるようにしました。

> ## ⚠ Firestore Rules を貼り直してください
>
> **今回は Rules を変えています。** 貼り直さないと、
> 契約者の画面でポイントがたまりません（書き込みが拒否されます）。
> 手順は末尾の「5. Rules の貼り直し」にあります。

---

## 1. 何ができるようになったか

| できること | 誰が | どこで |
|---|---|---|
| 毎日ひらくと 100pt たまる | 契約者（自動） | カレンダー画面の上 |
| 1日にたまる額を変える（既定 100） | 管理者 | 契約者ごとの設定画面 |
| ポイントを付ける／減らす | 管理者 | 新しい「ポイント」画面 |
| 個人・選択・全員に一斉に送る | 管理者 | 同上 |
| 送るときにお知らせを書く | 管理者 | 同上 |

---

## 2. 契約者から見えるもの

会員証のすぐ下に、ポイントの札が出ます。

- **ボタンはありません。開いた瞬間に、その日のぶんが入ります。**
  「受け取る」を押させると、押し忘れた日が出ます。
  押し忘れは本人の落ち度ではないのに、損をした気持ちだけが残ります。
- 入った日だけ「きょうのぶん +100 pt」が出ます。
  毎日同じ位置に出しておくと、入っていない日との違いが伝わりません。
- **何日休んでも、たまったぶんは減りません。**
  連続が途切れたらゼロに戻す形にはしていません。
  一度休んだ日にそのまま離れてしまうためです。

---

## 3. 1日の区切りは「朝4時」です

ご指定どおりです。**深夜0時ではなく、朝4時で切り替わります。**

| 開いた時刻 | どの日として数えるか |
|---|---|
| 9月6日 午前1時 | **9月5日**（まだ前の日） |
| 9月6日 午前3時59分 | **9月5日** |
| 9月6日 午前4時00分 | 9月6日 |
| 9月6日 昼・夜 | 9月6日 |

夜中に記録する人にとって、午前1時はまだ「昨日」です。
0時で切ると、夜更かしした日だけ2日ぶん入って、
早く寝た日は1日ぶんも入らない、ということが起きます。

---

## 4. ★ ここが今回いちばん大事なところです

**ポイントは、契約者が自分で書き換えられません。**

ポイントは実物と交換します。つまり本物の価値がある数字です。
会員ランクや既読の印とは、間違えたときの痛さが違います。

これまでのポイント（前の作り）は `extra` という自由な欄に入れていました。
**そこは契約者が何でも書ける場所です。** ブラウザの開発者ツールを開けば、
残高を 999999 にすることができました。飾りのバッジなら問題になりませんが、
実物と交換するとなると話が別なので、置き場所ごと変えました。

いまは、契約者にできるのは「今日ぶんを1回受け取る」ことだけです。
その1回も、次の全部が揃っていないとサーバー側で弾かれます。

1. 触る項目が、ポイント関係の4つだけであること
2. 日付が **サーバーの時刻の今日** であること（端末の時計は見ません）
3. 今日はまだ受け取っていないこと
4. 増える額が、**管理者が設定した1日ぶんぴったり** であること
5. 累計日数が、ちょうど 1 だけ増えること

1日の付与額そのものは管理者しか書けないので、
「額を自分で大きくしてから受け取る」もできません。

**画面を作り替えても、ブラウザから直接書いても、通りません。**

---

## 5. Rules の貼り直し

1. Firebase コンソール → Firestore Database → **ルール** タブ
2. `firebase/firestore.rules` の中身を**すべて**貼り付け
3. **公開** を押す

貼り直すまでは、契約者の画面でポイントがたまりません
（残高が0のまま増えません）。ほかの機能には影響しません。

---

## 6. ポイントを配る（管理者）

上のメニューに **「ポイント」** が増えています。

流れは、決める順番のとおりです。

```
1. 誰に      個人 / 選ぶ / 全員
2. ポイント  動かす？ → 何ポイント（マイナスで減らす）
3. お知らせ  見出しと本文
4. 確認      「〇人に +100 pt 送ります」→ 送信
```

### 減らす（交換したとき）

ポイント欄に **マイナス** を打つと減ります。`-500` のように入れてください。

- **残高より多く引いても、マイナスにはなりません。**
  300 しか無い人から 500 引こうとしたら、引けるのは 300 までです。
- 引ききれなかった人がいたときは、送ったあとの画面でそう伝えます。
  「引いた」と思ったまま帰されると、後から合わなくなるためです。

### お知らせ

- **ポイントが動いたときは、文面が空でも必ず1件届きます。**
  残高だけ変わって何も知らされないのが、いちばん不安にさせます。
  空のときは「ポイントが届きました」「ポイントを引きました」が入ります。
- ポイントを動かさず、**お知らせだけ**送ることもできます。
  「ポイントを動かす」のチェックを外してください。
- コメントのお知らせと違い、**送るたびに別の1件**として残ります。
  3回付けたなら3件残らないと、受け取った側が何をもらったか分からなくなります。

## 7. 1日にたまる額を変える

契約者ごとの設定画面（歯車）に **「ポイント」** の欄が増えています。

- 既定は **100**。0〜10000 の間で変えられます。
- **0 にすると、開いてもたまりません**（管理者が配るぶんだけになります）。
- いまの残高もここに出ますが、**ここでは動かせません。**
  付ける・減らすは「ポイント」画面からです。
  お知らせを添えずに残高だけ動くのを避けるためにそうしています。

---

## 8. 前に作りかけていた「ログインボーナス」から変わったところ

※ 前の版は**まだ配っていません**（GitHub に上げる前でした）。
実際に動くのは、今回のこの形が最初になります。

| | 前 | いま |
|---|---|---|
| 1日ぶん | 1pt（固定） | **100pt（管理者が変えられる）** |
| 日の区切り | 深夜0時 | **朝4時** |
| 置き場所 | `extra` の中（契約者が書ける） | **決まった項目（Rules で保護）** |
| 節目ボーナス | 7日/30日/100日/1年 | **やめました** |
| 管理者が付ける | できない | **できる（お知らせ付き）** |
| 管理者が減らす | できない | **できる** |

節目ボーナスをやめたのは、管理者が自由に付けられるようになったからです。
「+100pt ぴったり」という単純な形にしておくほうが、
サーバー側で守るときに隙間ができません。

**前の版は誰の手にも渡っていないので、移行もデータの手直しも要りません。**
