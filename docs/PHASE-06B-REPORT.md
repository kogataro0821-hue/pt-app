# Phase 6B 報告 — 運動と1日確定

Phase 6 の後半です。これで Phase 6 は完了になります。

## 1. できたこと

### 運動の記録（設計書 §22）

種目・時間（分）・内容の3つだけの、素直な記録です。

```
種目    ベンチプレス
時間    25 分
内容    60kg 10回 3セット
```

時間は未入力でも構いません（回数だけ記録したい種目もあるため）。

**★ 消費カロリーは扱いません。**

運動の消費カロリーは、どんな式を使っても推定値にしかなりません。
それを摂取カロリーと同じ画面に並べると、**食事の数字まで「だいたいの値」に見えてしまいます**。
このアプリの価値は数字が正確なことなので、推定値を混ぜるのは慎重に判断します。
必要になれば Phase 7 以降で、はっきり「推定」と分かる形で足します。

### 1日確定と解除（Q14の決定）

画面の一番下に「1日を確定する」が出ます。押すと、その日の記録が締められます。

確定すると:

- 上部に「この日は確定済みです」と出る
- 体重・食事・運動のすべての編集ボタンが消える
- 一番下が「確定を解除する」に変わる

**確定は「トレーナーへの提出」ではなく、「今日はもう食べません」という本人の意思表示です。**
だから、書き直したくなったら本人が解除できます（編集ウィンドウ内であればいつでも）。

それでも解除という一手間を残しているのは、
確定済みの日をうっかり上書きする事故を防ぐためです。

## 2. ★ Rules で表現した「解除だけは通す」

ここが今回いちばん神経を使った部分です。

確定済みの日は、食事も運動も体重も書き込めません。
しかし解除するには、その日ドキュメントを書き換える必要があります。
「書けないのに書かないと解除できない」という矛盾です。

そこで、**status を open に戻すだけの更新**に限って例外を作りました。

```
match /days/{date} {
  allow write: if mayEdit(cid, date);          // 確定済みなら通らない

  allow update: if isClient(cid)
                && inWindow(cid, date)
                && request.resource.data.status == 'open'
                && request.resource.data.diff(resource.data).affectedKeys()
                     .hasOnly(['status', 'finalizedAt', 'updatedAt']);
}
```

`hasOnly` が要です。これが無いと、
「解除にみせかけて体重も一緒に書き換える」という抜け道ができます。
そのケースもテストで塞いであります。

## 3. テスト

| 種類 | 件数 | 実行場所 |
|---|---|---|
| 単体テスト | 105件 | CI・毎回 |
| 権限テスト | 89件（+12） | CI・毎回（失敗したら公開しない） |

追加した権限テスト:

- 契約者は自分で確定を解除できる
- **確定したまま中身を書き換える経路は無い**
- **解除にみせかけて他の項目も同時に書き換えることはできない**（`hasOnly` の検証）
- 他人の確定は解除できない
- 管理者は確定を解除できる
- 契約者は今日を確定できる
- 契約者は他人の運動を書けない・一覧できない
- 10日前の運動は書けない（ウィンドウ外）

### CI で1度落ちたこと（記録）

最初の push で権限テストが落ちました。原因は Rules ではなく、**テストの前提データ**です。

確定済みの日として用意していたのが `2026-01-15` で、7か月以上前——
つまり編集ウィンドウ（7日）の外でした。そこで「本人が解除できる」を試せば、
当然拒否されます。Rules は正しく、テストの置き方が間違っていました。

確定済みの日を2種類（昨日＝ウィンドウ内 / 2026-01-15＝ウィンドウ外）用意し、
境界そのものをテストに変えました。

- ウィンドウ外の確定は、本人でも解除できない
- 確定済みなら、ウィンドウ内でも体重を書き換えられない

★ この失敗は「テストが仕事をした」例です。CI が公開を止めたので、
  穴のあるルールが本番に出ることはありませんでした。

## 5. 動作確認の手順

**契約者として**

1. 今日を開く → 「+ 運動を追加」→ `ベンチプレス` / `25` / `60kg 10回 3セット` → 保存
2. カレンダーに戻ると、その日に**青い点**が付いている
3. もう一度その日を開く → 一番下の「**1日を確定する**」を押す
4. 編集ボタンが全部消え、上に「確定済み」と出る
5. 「**確定を解除する**」を押す → また編集できるようになる

**管理者として**

1. 同じ日を開く → 運動と食事がそのまま見える
2. 確定済みの日でも編集できる

## 6. Phase 6 全体のまとめ

これで設計書の中心（§47）の**後半**が動くようになりました。

```
AI(推定) → 人間の確認 → 手動修正 → 確定 → 決定論的PFC計算 → 保存
   ↑                      ↑____________________________________↑
 Phase 8以降                        ここまで完成
```

食べたものを人が入力し、確認し、修正し、確定して、正確な数字が出る。
この骨格ができたので、あとはここに AI という「入口の楽をする仕組み」を足していく形になります。

**AI がどれだけ賢くなっても、計算は今日作った決定論的な関数が行います。**
