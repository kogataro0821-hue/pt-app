# Phase 7 報告 — 写真の添付と体重グラフ

## 1. 写真の添付

### なぜ「縮小」が処理の中心なのか

このアプリは Cloud Storage を使いません（カード登録が必要になるため）。
そこで写真は base64 にして Firestore のドキュメントに直接入れます。

ところが制約が2つあります。

1. Firestore の1ドキュメントは **1MiB まで**
2. base64 にすると、元データの **約1.37倍**に膨らむ

スマホで撮った写真はそのままだと3〜5MBあるので、**100%入りません**。
縮小は「あったほうがいい」機能ではなく、無いと動かない処理です。

### やっていること

```
1. 長辺 1280px に収まるよう縮める
2. 画質を 0.82 → 0.7 → 0.6 → 0.5 → 0.4 と落として、上限に収まるか試す
3. それでも収まらなければ、長辺を 1024 → 800 → 640 と縮めて 2 をやり直す
```

すべて**利用者の端末の中**で行います。大きな写真がそのまま回線に乗ることはありません。

`createImageBitmap` を使い、**EXIF の回転情報を反映**しています。
これが無いと、縦で撮った写真が横向きに保存されます。古い Safari では `<img>` に切り替えます。

透過PNGを JPEG にすると背景が黒くなるため、先に白で塗ってから描いています。

### ★ 見つけて直した境界の不具合

Rules 側は `dataUrl.size() < 400000`（**未満**）です。
一方こちらの判定は `bytes <= 400000`（**以下**）でした。

**ちょうど 400,000 バイトになった写真だけが保存に失敗する**という、
再現も原因究明も難しい不具合です。実際に踏む確率は低いですが、
踏んだときに「なぜかこの写真だけ保存できない」となる種類のものなので、
気づいた時点で直しました。両側とも「未満」に揃えています。

境界そのものを権限テストにしました。

- 399,999バイトは通る
- 400,000バイトは拒否される

### 差し替えできない仕様

写真は**消して撮り直す**形にしています（Rules でも `update` を禁止）。
確定した記録の写真だけが後から差し替わると、記録の意味が変わってしまうためです。

## 2. 体重グラフ

### 外部ライブラリを入れませんでした

必要なのは折れ線1本と目標線1本だけです。そのために数十KBの部品を読み込ませるのは、
通信の遅い場所で開く利用者に対して割に合いません。

座標の計算は `@pt/core` の純粋な関数にまとめ、描画は SVG で素直に書いています。
おかげで**グラフの挙動をテストできます**。

### 判断が入っているところ

**縦軸を0から始めません。** 体重を0から描くと、数kgの変化がまったく見えません。
実データの範囲に合わせ、上下に12%の余白を足しています。

**ただし最低2kgの幅を確保します。** 変化が小さいときに拡大しすぎると、
体重計の誤差が大きな増減に見えて、一喜一憂の元になるためです。

**目標値は必ず縦軸に含めます。** 目標線が画面の外にあると
「どれだけ離れているか」が分からず、グラフを見る意味が半分になります。

**横軸は実際の日数です。** 記録が飛んでいる日があるとき、点を等間隔に並べると
「毎日測っている」ように見えてしまいます。10日空いたら、その分だけ間隔も空きます。

**目標線は破線です。** 実測値と混同させないためです。

### 期間

1か月 / 3か月 / 1年 の3つ。「全期間」は用意していません。
続けるほど1回の表示が重く・高くなっていくためで、最長1年に区切っています。

## 3. テスト

| 種類 | 件数 | 実行場所 |
|---|---|---|
| 単体テスト | 125件（+20） | CI・毎回 |
| 権限テスト | 95件（+6） | CI・毎回（失敗したら公開しない） |

**グラフの計算（20件）**

目で見て判断しにくい部分なので、機械的に確認できる形にしました。

- 0からではなく実データの範囲に合わせる／実データを必ず含む
- 変化が小さくても最低2kgの幅を確保する
- 目標が離れていても縦軸を広げて必ず描く
- 記録の飛びが横方向の間隔に反映される
- すべての点が描画領域の中に収まる
- 点が0個・1個でも壊れない
- うるう年をまたいだ日数計算

**写真の権限（6件）**

- 上限ぎりぎり（399,999バイト）は通る／上限ちょうど（400,000バイト）は拒否される
- 契約者は他人の写真を保存できない・一覧できない
- 管理者は契約者の写真を見られる
- 確定済みの日には写真を足せない

## 5. 動作確認の手順

**写真**

1. `test01` でログイン → 今日を開く → 「写真」の「+ 写真を追加」
2. スマホなら「写真を撮る」か「ライブラリから選択」
3. 追加された写真をタップ → 拡大表示。大きさと容量が下に出る
4. 「×」で削除できる
5. 大きな写真（数MB）でも保存できることを確認してください。ここが今回の要です

**体重グラフ**

1. カレンダー画面の「体重の推移を見る」
2. 1か月 / 3か月 / 1年 を切り替える
3. 記録が2日ぶん以上あれば線が引かれ、「この期間で −◯kg」が出る
4. 目標体重を設定していれば、破線で目標線が出る

記録が1日ぶんしか無い場合、線は引かれず点だけになります（変化を語れないため）。

### 先に片付ける必要があること

AI を呼ぶには **APIキー**が要ります。これをアプリに埋め込むと、
リポジトリが公開なので誰でも読めて、他人にAIを使われてしまいます。

そこで **Cloudflare Workers**（無料・カード登録不要）に中継役を1つ置きます。

```
アプリ  →  Cloudflare Worker（キーを保持）  →  AI API
```

キーは Worker の中にだけ置かれ、アプリにもGitHubにも一切出ません。
