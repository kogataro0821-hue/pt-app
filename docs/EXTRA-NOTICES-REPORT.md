# 追加仕様の報告 — お知らせ欄

契約者の画面に、ベルとお知らせの一覧を足しました。
**Firestore Rules は変えていません。貼り直しは不要です。**

---

## 1. どこに出るか

契約者の画面の**右上にベル**が出ます。新しいお知らせがあると、数字が付きます。
押すと、お知らせの一覧（過去のぶんも読めます）が開きます。

**ベルは契約者だけに出ます。** 管理者に届くお知らせはありません（自分で書いたものだけになるため）。

---

## 2. お知らせは、自動で作られます

ご指定どおり、**管理者が手で書く欄は作っていません。**

| いつ | 出るお知らせ |
|---|---|
| 契約者アカウントを作ったとき | 登録が完了しました |
| あなたが「昇格させる」を押したとき | **〈ランク〉になりました** |
| あなたがコメントを保存したとき | **トレーナーからコメントが届きました**（その日へのリンク付き） |
| アプリを配ったとき | アプリが新しくなりました |

### なぜ「書く欄」にしなかったか

書く欄にすると、忙しい日は書かれません。
**書かれない欄は、契約者もやがて見なくなります。**
起きたことから自動で作れば、必ず出ます。

### 「アップデート情報」は、アプリに同梱です

Firestore には置いていません。**アプリの中の定数**です（`appNotices.ts`）。

配布のたびに、こちらで1行足します。**あなたの作業はありません。**
Firestore を使わないので、読み取りも書き込みも0回です。

### 降格では、お知らせを出しません

ランクを下げたことをアプリが通知するのは、**トレーナーの仕事を奪う形**になります。
伝えるなら、人の言葉で伝えるべき話です。

### 同じ日のコメントは、何度直しても1件

お知らせの目印を日付から作っています（`comment-2026-08-29` のような形）。
直すたびにお知らせが増えると、**ベルの数字ばかり大きくなって、中身が読まれなくなります。**

> ★ お知らせを出せなかったときでも、コメント自体は保存できています。
> お知らせが出ないだけのことで、書いた言葉を失うほうがずっと困ります。エラーも出しません。

---

## 3. 「閉じる」で、数字が消えます

一覧の上に「すべて閉じる」があります。押すとベルの数字が消えます。
**お知らせ自体は残ります。**あとから読み直せます（コメントの在りかを見失わないため）。

新しいお知らせが届けば、また数字が付きます。

### 1件ずつ閉じられるようにしなかった理由

既読を「ここまで読んだ」という**時刻1つ**で持っているためです。
1件ずつにすると、既読の印がお知らせと同じ数だけ増えます。
契約者が書ける場所は Rules で絞ってあり、小さく保ちたいところです。

### 管理者が見ても、既読になりません

あなたが様子を見に行っただけで既読になると、**本人はお知らせに気づかないまま終わります。**
管理者の画面では「すべて閉じる」を出していません。

---

## 4. 無料枠への配慮

**お知らせのための通信は、0回です。**

| 種類 | 置き場所 | 読み取り |
|---|---|---|
| 個人あて | 契約者ドキュメントの中（配列・直近30件） | **0回**（元から読んでいる） |
| 全員向け | アプリの中の定数 | **0回**（Firestore に無い） |
| 既読の印 | 同じく契約者ドキュメントの中 | 同上 |

別のコレクションにすると、画面を開くたびに読み取りが増えます。
契約者ドキュメントはカレンダーを開いた時点ですでに読んでいるので、その中に入れました。
**ベルの数字も、一覧の中身も、追加の通信なしで出ます。**

そのかわり無限には溜められないので、**30件**で切っています（古いものから消えます）。
1日1件のコメント通知でも1か月ぶん残る計算です。

書き込みは、コメントを保存したときに +1回、昇格させたときに +1回、契約者が「閉じる」を押したときに +1回だけです。

---

## 5. Rules を1行も足していない理由

会員ランクのときと同じ仕組みです。

`clients` の書き込みで**契約者に許した項目は、Rules に名指しで6つ**書いてあります。

```
displayName / memo / extra / aiConsent / passwordChangedAt / updatedAt
```

`notices` はこの中に入っていません。**足すだけで、自動的に管理者専用**になります。

| 試したこと | 結果 |
|---|---|
| 契約者が自分あてのお知らせを作る | **弾かれる** |
| 契約者が届いたお知らせを消す（空にする） | **弾かれる** |
| 表示名の更新に紛れ込ませる | **弾かれる** |
| 他人あてのお知らせを作る | **弾かれる** |
| 契約者が自分の既読を付ける | 通る（`extra` の中なので） |
| 契約者が他人の既読を付ける | **弾かれる** |

「トレーナーからコメントが届きました」を本人が作れてしまうと、
お知らせは記録ではなく、ただの飾りになります。

> ★ ただし、この安全は**「一覧に入っていない」ことだけ**で成り立っています。
> 一覧に1語足した瞬間に消えますし、Rules の差分は「許可を足した」ようにしか見えません。
> そこで見張りを1つ足しました（`firebase/tests/coverage.test.ts`）。
> 一覧を機械的に読んで、`rank` / `memberNo` / `notices` / `targets` などが
> 紛れ込んでいないかを毎回確かめます。**ためしに `notices` を足してみたところ、正しく落ちました。**

### 使い始めるとき

いまいる契約者には、まだ個人あてのお知らせがありません（これから起きたことから作られます）。

> ★ 動作を試すなら、いちばん早いのは**その契約者の日別画面でコメントを1件保存する**ことです。

## 8. 直した不具合（お渡ししたあとに見つかったもの）

**お知らせ1件が、縦に何画面ぶんも空いていました。**

種類を示す小さな札に、種類の名前をそのまま class として付けていました。

```
class="badge notice-kind app"
                        ~~~
```

ところが `app` は、**アプリ全体の外枠がすでに使っている class** です。

```css
.app { min-height: 100dvh; display: flex; flex-direction: column; }
```

その結果、小さな札が画面いっぱいの高さになりました。

接頭辞を付けて直しました（`notice-kind-app`）。

> ★ 見た目の確認をしていたのに、気づけませんでした。
> **4種類のうち `app` だけ**が壊れていて、確認に使った見本に `app` が
> 入っていなかったためです。「代表的な1つを見る」では足りませんでした。
>
> 再発防止として、テストで**4種類すべて**を並べ、
> 種類の名前が裸の class になっていないことを確かめるようにしました。
> ためしに元の書き方に戻したところ、正しく落ちました。
> 見た目の確認でも、4種類すべてを並べて描かせています。

## 9. アイコンとアプリ名

**ホーム画面のアイコンを、たろZAP のマークにしました。**

| ファイル | 使われる場所 |
|---|---|
| `apple-touch-icon.png`（180px） | **iPhone のホーム画面** |
| `icon-192.png` / `icon-512.png`（512px） | Android のホーム画面・アプリ一覧 |
| `icon-512-maskable.png` | Android の「好きな形に切り抜く」アイコン |
| `favicon.png`（96px） | ブラウザのタブ |

`favicon.svg` は使わなくなったので消しました（**このファイルだけは、上書きでは消えません。手で削除してください**）。

> ★ マスク用の1枚だけ、ロゴを 80% に縮めて黒で余白を足してあります。
> Android は端末ごとに丸・角丸・雫など好きな形に切り抜き、
> **確実に残るのは中央の直径80%の円の内側だけ**です。
> そのまま入れると、いちばん外の金の輪が切れます。

**アプリ名を「PT Manager」から「たろZAP」に変えました。**

アイコンがたろZAP なのに、その真下に「PT Manager」と出るのはちぐはぐでした。
書き換えたのは3箇所です。

| 場所 | 何に出るか |
|---|---|
| `vite.config.ts` の `short_name` | Android のホーム画面のアイコン下 |
| `index.html` の `apple-mobile-web-app-title` | **iPhone のホーム画面のアイコン下** |
| `index.html` の `<title>` | ブラウザのタブ |
| `src/config/firebase.ts` の `APP_NAME` | 画面上部とログイン画面 |

> ★ すでにホーム画面に追加している端末では、**アイコンも名前も変わりません。**
> 追加した時点の絵と名前が焼き付くためです。
> 一度ホーム画面から削除して、追加し直してもらってください。
> 中身のアップデートには影響しません。
