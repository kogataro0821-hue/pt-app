# 追加仕様の報告 — 登録依頼のAI

登録依頼の画面に「AIに下書きを作らせる」を足しました。
**Firestore Rules は変えていません。貼り直しは不要です。**

---

## 0. 先に、いちばん大事なこと

**AI はマスタに1バイトも書きません。**

作るのは下書きだけです。確定するのは、あなたが値を見て、登録の画面で保存したときです。

マスタの1件は、**全契約者の集計に効きます。** ほかの画面なら「あとで直せばいい」で済みますが、
ここは違います。間違った値が入ると、それを使った全員の過去の数字が狂います。
だから AI が直接触れる経路を作っていません（設計書 §47）。

---

## 1. AI がすること（3つ）

依頼を開いて **「AIに下書きを作らせる」を押したときだけ** 動きます。

| | 出るもの |
|---|---|
| **① 栄養値** | 100gあたりの kcal / P / F / C の推定値 |
| **② 表記ゆれ** | 「鶏むね肉」→「鶏ムネ肉」「とりむね」などの別名の案 |
| **③ まとめ先** | すでにマスタにある同じ食材（あれば） |

あわせて「**どういう食品として答えたか**」も出します（例:「皮なしの鶏むね肉（生）」）。
これがあると、AI が別の食品として答えていたときに気づけます。

### 開いただけでは聞きません

自分で分かる食材にも回数を使ってしまいます。AI の利用は1人1日50回までです。
**押したときだけ**にしました。

### 「分からない」と言わせています

per100g は、AI が **null（分からない）を返せる形**にしてあります。

必ず数字を返させると、AI は分からなくても何か入れます。
埋める欄があるから埋める、というのが設計書 §12 が禁じている補完そのものです。
**それらしい数字を作らせるより、分からないと言わせるほうが安全です。**

---

## 2. AI に送るもの

| 送るもの | 送らないもの |
|---|---|
| 食材の名前（1つ） | 誰が依頼したか（契約者ID・表示名） |
| マスタにある食材の**名前**（最大300件） | いつ・何回食べたか |
| | 契約者が入れた仮の値 |
| | 成分表示の写真 |
| | マスタの栄養値 |

**誰の記録かを、AI 側で結び付けられません。** 送っていないからです（設計書 §35）。

> ★ マスタの名前を送るのは、③「すでにある食材と同じか」を見るためです。
> これは**全員で使う辞書**であって、誰か個人の情報ではありません。
> 栄養値は送っていません（名前だけで足ります）。

---

## 3. ★ 返ってきたものは、必ず関門を通します

AI の返事を画面にそのまま出しません。**機械で分かる嘘は、人に見せる前に落とします。**

人の目だけに頼ると、忙しい日に素通りします。しかも「AIが言うなら」で通してしまいます。

### ① ありえない数値を落とす

| 見ているもの | 例 |
|---|---|
| P+F+C が 100g を超えていないか | 100g の中に 120g は入りません |
| 100gあたり 900kcal を超えていないか | いちばん高い純粋な脂質で900kcalです |
| マイナスが入っていないか | |
| PFC が全部0なのに熱量だけないか | 名前だけ見て kcal を埋めた形 |

**ありえない値は、画面にも出しません。** 出すと「まあ近いかも」で採用されます。理由だけを伝えます。

### ② 計算の食い違いに印を付ける

たんぱく質4・脂質9・炭水化物4 kcal で計算し、申告された kcal と比べます。
大きく外れていたら「⚠ 計算が合いません」と出します。

> ★ ただし**止めはしません。** 食物繊維は炭水化物に数えられますが熱量はほとんどありません。
> 糖アルコールやアルコールもずれます。**合わない＝間違い、ではありません。**
> 厳しくしすぎると正しい値まで警告だらけになり、警告そのものが読まれなくなります。

### ③ 実在しない「まとめ先」を捨てる

**AI は、渡していない名前を平気で返します。**

「鶏むね肉」しか渡していないのに「鶏胸肉（皮なし）」と返す、という形です。
そのまままとめると、**存在しない食材へ寄せる**ことになります。

渡した一覧に本当にあるかを、こちらで照合します。無ければ捨てて、そのことを画面に出します。

### ④ ぶつかる別名を捨てる

すでに他の食材が使っている名前は、別名にできません。
入れると、その言葉が**どちらの食材に当たるか決まらなくなります。**
マスタの引き当てが壊れる、いちばん静かな壊れ方です。

別名は**5個まで**にしています。多いほど便利に見えますが、1つ間違えると別の食材に当たります。

### ★ 捨てたときは、黙りません

「使えない別名を外しました。「ごはん」すでに「白米」が使っています。」のように出します。
黙って消すと、AI が何を言ったのかが分からなくなり、人が判断し直せません。

---

## 4. 無料枠とAIの回数

- **押したときだけ**呼びます。1回の依頼につき1回です
- AI の利用は1人1日50回まで（Cloudflare Worker 側の制限。前に入れたものです）
- Firestore の読み書きは**増えていません**。マスタも依頼も、画面を開いた時点ですでに読んであります

### 固定した約束（主なもの）

| 確かめたこと |
|---|
| **★ 開いただけでは、AIに聞かない**（押したときだけ） |
| **★ 送るのは食材名とマスタの名前だけ**（誰の記録かは送らない） |
| 栄養値そのものは送らない |
| **★ 下書きが出ても、マスタには何も保存されない** |
| 「入力欄に入れる」は受け渡しだけ／メモに「要確認」が残る |
| **★ ありえない値は、採用ボタンごと出さない** |
| P+F+C>100g／900kcal超／マイナス／中身が空なのに熱量だけ、を弾く |
| **★ 計算が合わないときは、値は出すが印を付ける**（止めはしない） |
| 少しのずれでは警告しない（警告だらけにしない） |
| **★ マスタに無い「まとめ先」は、押せる形で出さない** |
| 捨てたことを、黙らずに伝える |
| **★ 他の食材が使っている別名は、出さない** |
| いま登録する名前そのものは別名にしない／重複はまとめる／5個まで |
| **★ 「分からない」を、そのまま受け取る**（無理に数字を出させない） |
| AIに聞けなかったら、そのことを出す／失敗しても下書きは出ない |

> ★ 関門を1つずつ壊してみて、どれもきちんと落ちることを確かめてあります。
> 関門を丸ごと外したときは4件、まとめ先と別名の照合を外したときは5件が落ちました。

## 6. お願い

| 変えたもの | あなたの作業 |
|---|---|
| `firebase/firestore.rules` | **変えていません。貼り直し不要です** |
| `worker/worker.js` | 変えていません |
| アプリ本体 | push すれば自動で配られます |

### 使い方

1. 「登録依頼」を開く
2. 依頼を開く
3. **「AIに下書きを作らせる」**を押す
4. 出てきた値を見て、使うなら「この値を入力欄に入れる」
5. 登録の画面で確かめて、保存

**4 と 5 は別です。** 入れただけでは保存されません。
