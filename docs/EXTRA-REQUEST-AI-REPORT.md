# 追加仕様の報告 — 登録依頼のAI

登録依頼の画面に「AIに下書きを作らせる」を足しました。
**Firestore Rules は変えていません。貼り直しは不要です。**

---

## 0. 先に、いちばん大事なこと

**AI はマスタに1バイトも書きません。**

作るのは下書きだけです。確定するのは、あなたが値を見て、登録の画面で保存したときです。

マスタの1件は、**全契約者の集計に効きます。** ほかの画面なら「あとで直せばいい」で済みますが、
ここは違います。間違った値が入ると、それを使った全員の過去の数字が狂います。
だから AI が直接触れる経路を作っていません（設計書 §47）。

---

## 1. AI がすること（3つ）

依頼を開いて **「AIに下書きを作らせる」を押したときだけ** 動きます。

| | 出るもの |
|---|---|
| **① 栄養値** | 100gあたりの kcal / P / F / C の推定値 |
| **② 表記ゆれ** | 「鶏むね肉」→「鶏ムネ肉」「とりむね」などの別名の案 |
| **③ まとめ先** | すでにマスタにある同じ食材（あれば） |

あわせて「**どういう食品として答えたか**」も出します（例:「皮なしの鶏むね肉（生）」）。
これがあると、AI が別の食品として答えていたときに気づけます。

### 開いただけでは聞きません

自分で分かる食材にも回数を使ってしまいます。AI の利用は1人1日50回までです。
**押したときだけ**にしました。

### 「分からない」と言わせています

per100g は、AI が **null（分からない）を返せる形**にしてあります。

必ず数字を返させると、AI は分からなくても何か入れます。
埋める欄があるから埋める、というのが設計書 §12 が禁じている補完そのものです。
**それらしい数字を作らせるより、分からないと言わせるほうが安全です。**

---

## 2. AI に送るもの

| 送るもの | 送らないもの |
|---|---|
| 食材の名前（1つ） | 誰が依頼したか（契約者ID・表示名） |
| マスタにある食材の**名前**（最大300件） | いつ・何回食べたか |
| | 契約者が入れた仮の値 |
| | 成分表示の写真 |
| | マスタの栄養値 |

**誰の記録かを、AI 側で結び付けられません。** 送っていないからです（設計書 §35）。

> ★ マスタの名前を送るのは、③「すでにある食材と同じか」を見るためです。
> これは**全員で使う辞書**であって、誰か個人の情報ではありません。
> 栄養値は送っていません（名前だけで足ります）。

---

## 3. ★ 返ってきたものは、必ず関門を通します

AI の返事を画面にそのまま出しません。**機械で分かる嘘は、人に見せる前に落とします。**

人の目だけに頼ると、忙しい日に素通りします。しかも「AIが言うなら」で通してしまいます。

### ① ありえない数値を落とす

| 見ているもの | 例 |
|---|---|
| P+F+C が 100g を超えていないか | 100g の中に 120g は入りません |
| 100gあたり 900kcal を超えていないか | いちばん高い純粋な脂質で900kcalです |
| マイナスが入っていないか | |
| PFC が全部0なのに熱量だけないか | 名前だけ見て kcal を埋めた形 |

**ありえない値は、画面にも出しません。** 出すと「まあ近いかも」で採用されます。理由だけを伝えます。

### ② 計算の食い違いに印を付ける

たんぱく質4・脂質9・炭水化物4 kcal で計算し、申告された kcal と比べます。
大きく外れていたら「⚠ 計算が合いません」と出します。

> ★ ただし**止めはしません。** 食物繊維は炭水化物に数えられますが熱量はほとんどありません。
> 糖アルコールやアルコールもずれます。**合わない＝間違い、ではありません。**
> 厳しくしすぎると正しい値まで警告だらけになり、警告そのものが読まれなくなります。

### ③ 実在しない「まとめ先」を捨てる

**AI は、渡していない名前を平気で返します。**

「鶏むね肉」しか渡していないのに「鶏胸肉（皮なし）」と返す、という形です。
そのまままとめると、**存在しない食材へ寄せる**ことになります。

渡した一覧に本当にあるかを、こちらで照合します。無ければ捨てて、そのことを画面に出します。

### ④ ぶつかる別名を捨てる

すでに他の食材が使っている名前は、別名にできません。
入れると、その言葉が**どちらの食材に当たるか決まらなくなります。**
マスタの引き当てが壊れる、いちばん静かな壊れ方です。

別名は**5個まで**にしています。多いほど便利に見えますが、1つ間違えると別の食材に当たります。

### ★ 捨てたときは、黙りません

「使えない別名を外しました。「ごはん」すでに「白米」が使っています。」のように出します。
黙って消すと、AI が何を言ったのかが分からなくなり、人が判断し直せません。

## 4. 無料枠とAIの回数

- **押したときだけ**呼びます。1回の依頼につき1回です

- Firestore の読み書きは**増えていません**。マスタも依頼も、画面を開いた時点ですでに読んであります

## 7. 成分表示の写真があるときは、写真が上

**契約者が撮った成分表示の流れは、何も変えていません。**

1. 契約者が成分表示を撮る → その場でAIが読み取る（契約者の端末で）
2. 読み取った値と**写真そのもの**が、登録依頼として届く
3. あなたが写真と数字を見比べて確認 → 登録

写真は依頼を開いている間ずっと出ますし、「新しく登録する」を押しても消えません。
読み取り直しもしません（契約者側で一度読んでいます）。

### ★ ただし、1つ危ないところがありました

写真がある依頼でも、AI のボタンが**同じ顔で**出ていました。
そこで「この値を入力欄に入れる」を押すと、
**写真から読み取った値が、AI の推測で上書きされます。**

写真には実物の裏付けがあります。AI の推定にはありません。順番が逆です。
以前「契約者が手で入れた仮の値」と「写真つき」を区別したのと、同じ性質の問題です。
**同じ顔で並べると、確かめずに採用されます。**

3つ直しました。

| | |
|---|---|
| 聞く前 | 「この依頼には成分表示の写真があります。**そちらのほうが確かです。**」 |
| 押す前 | 「⚠ 押すと、成分表示から読み取った値が、この推定で置き換わります。」 |
| ボタン | 「この値を入力欄に入れる」→ **「読み取った値を、この推定で置き換える」** |

> ★ **止めはしません。** 写真がぼやけて読めていないこともあります。
> 決めるのは人です。ただし、何が起きるかを知ったうえで決められるようにします。

別名とまとめ先は、写真の有無に関係なく普通に使えます（数値とは別の話なので）。

## 8. 使ってみて出た2つ（この版で直しました）

### ★ 値と別名の、どちらか一方しか取り込めなかった

**私のバグです。**

片方のボタンを押した瞬間に登録の画面へ進む作りにしていました。
すると下書きの画面が閉じ、**もう片方を押せなくなります。**

進むのは「新しく登録する」を押したときだけにしました。
いまは値も別名も取り込めて、取り込んだものは
「登録の画面に持っていくもの」としてその場に出ます。

> ★ ボタンの文字も「取り込みました」に変わります。
> 押しても画面が変わらないと、効いたのかどうか分かりません。

### ★ 成分表示の読み取りが重かった

2つ手を打ちました。

**① 考える時間を0にしました**

`gemini-2.5-flash` は、既定で答える前に内部で考えます。
筋道を立てる問いには効きますが、**成分表示の数字を書き写す仕事には要りません。**
考えるぶんだけ待ち時間が伸びます。

抽出の4つ（文章から／写真から／成分表示から／登録依頼の下書き）で、考える時間を0にしました。

**評価文だけは、いままでどおり考えさせています。**
あちらは人に読ませる文章を組み立てる仕事で、考える価値があります。
速さだけを見て、どこにでも同じ設定を入れてはいけません。

> ★ **保険を付けてあります。** この設定が通らないモデルだと 400 で返ってきます。
> そのとき読み取りごと失敗させると、**速くしようとして壊した**ことになります。
> 設定を外して1回だけやり直します。速さより、動くことが先です。
>
> やり直すのは「考えない設定が原因だ」と応答から分かるときだけです。
> どんな400でもやり直すと、鍵の設定ミスのようなときに1日の回数を2つ食べてしまいます。

**② 成分表示の写真を小さくしました（長辺 1280px → 1000px）**

成分表示は「数字が読めればよい」だけで、盛り付けの様子は要りません。
送る量も AI が見る量も減ります。食事の写真は 1280px のままです。

> ★ どちらも待ち時間を**短くする**手ですが、どれだけ短くなるかは
> こちらでは計れません（実機の回線とモデルの混み具合によります）。
> 変わらないようなら、次は「読み取りの途中経過を出す」方向で考えます。
