# Phase 8B 報告 — 写真からの推定

## 1. 設計上の課題

Phase 8A では、AIの勝手な補完を**3層**で受け止めていました。

1. 指示（何が禁止かを具体例で示す）
2. 欄を絞る（栄養値の欄を作らない）
3. **原文照合**（根拠が入力文に無ければ機械的に破棄）

写真では、この3が丸ごと使えません。**照合する原文が存在しない**からです。

一番効いていた防御が消えるので、別の形で釣り合いを取る必要がありました。

## 2. 代わりに置いた3つ

### (1) 量を「幅」で答えさせる

`180g` と1点で言い切らせず、`150〜210g` の形で答えさせます。

**幅の広さが、そのまま自信の無さとして目に見えます。**
「たぶん180gだが100〜250gかもしれない」なら、正直にそう答えさせる。
指示にも「幅を狭く見せる必要はありません。狭いほど良い、ということはありません」と明記しています。

画面には「推定 / AIの見立て: 150〜210g」と並べて出します。
数字だけを見せると、推定が事実に見えてしまうためです。

### (2) 写真から来た項目は、1つも自動採用しない

テキストでは、根拠が照合できて確信度も高ければ「そのまま使える」扱いにしていました。
写真では**その経路を作りません**。すべて確認待ちとして人に見せます。

型の上でも `needsUserInput` を常に true にしてあり、
`quantityStatus` が `confirmed` になる経路が存在しません。

### (3) 入口の閾値を厳しくする

確信度の下限を、テキストの `0.6` に対して **`0.75`** にしました。
後ろ盾が無いぶん、入口で絞ります。

落とした項目は「自信が低いため取り除いた項目」として理由付きで表示します。

## 3. 根拠の書かせ方

写真では照合できませんが、**人が見比べられる形**にはできます。

```
根拠: 手前の茶碗に盛られた白いごはん
根拠: 奥の角皿にある、焼き色のついた鶏肉
```

「どこを見てそう判断したか」を書かせることで、利用者が写真と照らして確かめられます。
機械的な検証の代わりに、人の検証を成立させる材料を渡す、という考え方です。

## 4. その他の判断

**量は最初から入れておきます**（テキストでは入れません）。

写真の場合、推定値を入れておくことに意味があります。それが機能の目的だからです。
ただし「入れておく」ことと「確定させる」ことは別です。
推定であることと幅を必ず並べて出し、人が見比べて直せるようにしています。

一方テキストでは、書かれていない量を勝手に埋めることはしません。
書いていないものは、書いていないからです。

**AIの質問は、量が埋まっていても表示します。**
「皮は付いていましたか？」のように量とは別のことを聞いている場合があり、
量が入ったからという理由で握りつぶすと、確認の機会が失われます。

**写真は端末の中で縮小してから送ります**（Phase 7 の仕組みをそのまま使用）。
数MBの写真がそのまま回線に乗ることはありません。

## 5. テスト

| 種類 | 件数 | 実行場所 |
|---|---|---|
| 単体テスト | 169件（+12） | CI・毎回 |
| 権限テスト | 95件 | CI・毎回 |

写真解析について追加した12件:

- **確信度が高くても、写真の項目は自動採用されない**
- **確信度1.0でも confirmed にはならない**
- 推定の幅を保持する / 上限と下限が逆でも直す / 幅が無ければ表示しない
- 栄養値・ブランド名・調理法が一切入らない
- 写真の閾値がテキストより厳しい
- 特定できなかったものは食品として登録されない
- 根拠が空・負の量を受け付けない

## 6. 公開前の作業

**Firestore Rules の変更はありません。** 貼り直しは不要です。
**Worker の変更もありません。** 写真も同じ中継役を通ります（本文の上限2MBに収まります）。

アプリの更新（Commit / Push）だけで反映されます。

## 7. 動作確認の手順

1. 契約者でログイン → 今日 → 食事の「**写真から**」
2. 食事の写真を選ぶ（撮影でも可）
3. 補足があれば書く（「ごはんは少なめ」など。空欄でも可）
4. 「この写真を読み取ってもらう」

**見ていただきたいところ**

- 「写真から読み取った**推定**です」の帯が出るか
- 各項目に「**推定 / AIの見立て: ◯〜◯g**」が出るか
- 根拠が「手前の茶碗に…」のように、**写真のどこを見たか**で書かれているか
- 判別できないものが `unidentified` に逃げているか（勝手に食品名を当てていないか）
- 写っていないもの（味噌汁、ドレッシングなど）を足していないか

最後の2つが、この Phase の肝です。

## 8. Phase 8 完了

```
AI(推定) → 人間の確認 → 手動修正 → 確定 → 決定論的PFC計算 → 保存
  文章 ✅
  写真 ✅
```

AIがどれだけ賢くなっても、kcal と PFC の計算に触れることはありません。
AIの仕事は「何が・どれだけ」までで、そこから先は Phase 1 で作った決定論的な関数の領分です。
