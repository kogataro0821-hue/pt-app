## 2. 何が抜けていたのか

161件ありました。数だけ見れば十分に思えます。
ルールの `match` ブロックと `allow` 文を1つずつ数えたところ、こうでした。

### テストが1件も無かった場所（5つ）

| 場所 | 何が置かれるか | 危なさ |
|---|---|---|
| `clients/{cid}/aiSessions/{sid}/messages/{mid}` | **AIとの会話の本文**。何を食べたかがそのまま入る | 最大 |
| `clients/{cid}/favorites/{fid}` | お気に入り | 大 |
| `clients/{cid}/recipes/{rid}` | 個人のレシピ | 大 |
| `/recipes/{rid}` | 共通レシピ | 中 |
| `match /{document=**}` | **既定の全拒否** | 大 |

**`messages` が最も重いです。** 親の `aiSessions` には「他人が読めない」テストが1件ありましたが、
**本文が入るサブコレクションには読み取りも書き込みも1件もありませんでした。**
契約者どうしの分離が、この場所については一度も確かめられていなかったということです。

`match /{document=**}` は、ルールに書き忘れたパスを塞いでいる1行です。
ここが `if false` から外れると、**書き忘れた場所すべてが誰でも読み書きできる状態**になります。
その1行を試すテストが、ありませんでした。

### そのほか、埋めた主な穴

| 穴 | なぜ危ないか |
|---|---|
| 他人の体重記録への**書き込み**が未検証 | 読み取り側だけテストがあった |
| 他人の変更履歴への**書き込み**が未検証 | 偽の監査記録を差し込めるか確かめていなかった |
| `photoOldestAt` の抜け道を**他人が使えるか**が未検証 | この経路は期間も確定状態も見ない。`isClient(cid)` 1本で守っている |
| `users` の **list / create / delete** を契約者が試すテストが無い | 一覧できると他人のUIDと役割が見える |
| `clients` の **delete** を契約者が試すテストが無い | |
| 日データの **delete** がまったく未検証 | 誰も削除を試していなかった |
| 未認証のテストが**6件しかなかった** | 日次データ・写真・評価・コメント・体重・履歴はすべて未検証 |
| 契約者が**開いている日を更新する**成功経路が未検証 | ここが常に false になっても、テストは緑のままアプリだけ壊れる |

## 3. 新しく分かったこと

テストを書く過程で、ルールの挙動が2つはっきりしました。どちらも**不具合ではありません**が、
知らないと困るので記録します。

### 3-1　`permissions` が無い契約者は、日付に紐づく書き込みができません

移行前のかたちで `clients/{cid}` に `permissions` が無い場合、
`inWindow()` が日数を取り出せず、ルールの評価そのものが失敗します。
Firestore はこれを**拒否**として扱うので、その契約者は食事も運動も書けません。

読むことはできます。直すには、その契約者に `permissions` を入れ直します。

**通してしまうより止めるほうが安全**なので、この挙動は変えていません。
テスト（`permissions が無い古いかたちの契約者は…`）で固定しました。

### 3-2　役割が変な値のユーザーは、何も読めません

Firebase Auth には誰でも登録できます（apiKey は公開情報なので隠せません）。
`users` ドキュメントは管理者しか作れないので塞がっていますが、
**役割が `admin` でも `client` でもない値だったとき**にどうなるかは、確かめていませんでした。

`isKnownUser()` が役割を見ているので、共通マスタも設定も読めません。テストで固定しました。
あわせて、**無効にされた管理者**が管理者として扱われないことも確かめています。

## 4. 同じ見落としを繰り返さないために

テストを足すだけでは、**次に新しいコレクションを足したとき、また同じことが起きます。**
104件書いても、来月ルールに1行足してテストを書き忘れれば、そこは空白になります。

そこで、見張りを作りました（`firebase/tests/coverage.test.ts`、25件）。

| 見張るもの | 破れたときに出るもの |
|---|---|
| ルールの `match` ブロックすべてに、テストが1件以上ある | 「ルールに match /◯◯ がありますが、一度も触っていません」 |
| 既定の全拒否（`if false`）が残っている | |
| 既定の全拒否を試すテストがある | |
| `signedIn()` がログインの有無を見ている | |
| `isAdmin()` に「有効なアカウントか」が入っている | |
| `isClient()` に「本人かどうか」の比較が入っている | |

**この見張りはエミュレータを使いません。** ファイルを読んで突き合わせるだけなので、
`npm run verify` に乗せてあり、**どこでも・CIでも毎回走ります。**

わざとルールを壊して、実際に止まることを確かめました。

- ルールに `match /brandNewThing` を足す → 「テストを足すか、使わなくなった match ブロックを消してください」で赤
- 既定の全拒否を `if true` に変える → 赤
